# 추천 데이터 기반 서비스 방향

> 근거 문서: `recommendation_data_decisions.md` (사용자가 제공한 2026-08-26 결정 기록)
>
> 이 문서는 첨부된 결정 기록에서 서비스 구현에 필요한 제약만 추려 반영한 방향 문서다. 첨부 문서의 수치는 기준 데이터셋에 대한 실측값이므로 코드의 영구 상수로 간주하지 않는다.

## 1. 서비스가 제공할 가치

서비스는 두 가지 문제를 분리해서 해결한다.

1. **찾을 수 있어야 한다.** 검색·상세·찜의 카탈로그는 국립중앙도서관과 정보나루 도서 메타데이터의 ISBN13 합집합으로 구성한다. 한 출처에 없다는 이유로 검색 대상에서 제외하지 않는다.
2. **지금 읽을 책을 잘 골라야 한다.** 추천은 도서관 대출 수요와 신간을 기반으로 후보를 만들고, 사용자 서재·평점·초기 취향으로 개인화한다.
3. **로그인 후 기록이 쌓일수록 정교해져야 한다.** 신규 로그인 사용자는 초기 취향이나 세그먼트 인기 기반의 콜드스타트 추천을 받고, 이후 조회·좋아요·평점·서재 데이터를 추가해 개인화한다.

도서관별 원장은 MVP API가 직접 제공하지 않는다. 추천 수요 산출에 필요한 외부 대출 스냅샷만 배치 입력으로 사용하고, 근처 도서관 조회는 다음 버전으로 미룬다.

## 2. 데이터 계층

```text
L0 카탈로그
  국중 ISBN ∪ 정보나루 ISBN
  + ISBN 미등재 검색 시 카카오 1회 온디맨드 등록
       │
       ├─ 검색·상세·찜·서재의 전체 도서 표면
       │
       └─ L1 추천 후보
            ├─ 누적 대출로 전체 수요 99%를 유지하는 임계 통과 도서
            └─ 대출 이력이 없어도 포함하는 신간 트랙

외부 대출 원장(배치 입력)
       │
       └─ 월별 차분 → 추천 수요 feature
```

## 3. 추천 모드

추천 API는 로그인 여부에 따라 입력과 결과의 의미를 명확히 분리한다.

| 모드 | 인증 | 추천 입력 | 점수 계산 | 결과 저장 |
| --- | --- | --- | --- | --- |
| `PERSONALIZED` | 필요 | 조회·좋아요·평점·서재·seed book·관심 태그 | 개인 `taste` + 수요·신규성 등 최종 가중치 | `userId` 기준 스냅샷 저장 |
| `COLD_START` | 필요 | 로그인 사용자의 초기 취향·세그먼트 | 초기 취향 태그·세그먼트 인기·수요 | `userId` 기준 스냅샷 저장 |

모든 추천은 로그인 사용자 기준으로 생성하고 저장한다. 초기 취향 데이터가 없는 사용자는 `COLD_START`, 충분한 행동 데이터가 쌓인 사용자는 `PERSONALIZED` 모드로 처리한다.

### L0 카탈로그 규칙

- `book_source_records.source`가 `NATIONAL_LIBRARY` 또는 `DATA4LIBRARY`인 ISBN13을 기본 카탈로그로 합친다.
- 같은 ISBN13은 하나의 `books`로 정규화하고 출처별 레코드는 덮어쓰지 않는다.
- ISBN13이 없는 원본은 `book_source_records`에 보관할 수 있지만 검색·추천용 canonical `books`로 확정하지 않는다.
- L0에 없는 ISBN 검색 요청은 카카오에서 한 번 조회하고, 유효한 ISBN13과 최소 서지 정보가 있으면 `books`와 `book_source_records`에 등록한다.
- 제목만으로 서로 다른 ISBN 판본을 병합하지 않는다.

### L1 추천 후보 규칙

- 대출 후보는 누적 대출량 상위 절대 개수가 아니라 **전체 대출 수요의 99%를 유지하는 최대 임계**로 선택한다.
- 신간 후보는 국중 2025년 이후 도서 중 대출 데이터에 아직 유입되지 않은 도서를 별도 트랙으로 포함한다.
- 두 트랙은 합집합으로 만들고, 후보가 조금 넓어지는 비용은 랭킹에서 낮아지는 비용으로 처리한다.
- 텍스트가 있다는 이유로 후보를 미리 제거하지 않는다. 텍스트 확보는 별도 보강 단계다.
- 외서는 L0에서 일괄 제거하지 않는다. L1 제외가 필요하면 영어 원서 등 타깃 정렬과 손실을 명시한 정책으로 분리한다.

## 4. 인기 랭킹과 갱신

정보나루 월 파일의 대출량은 해당 기간의 신규 대출량이 아니라 데이터 제공 개시 이후의 누적 스톡이다. 따라서 최근 수요는 누적값 자체가 아니라 스냅샷 차분으로 계산한다.

```text
loan_24m = max(0, cumulative_latest - cumulative_24_months_ago)
loan_3m  = max(0, cumulative_latest - cumulative_3_months_ago)
rank_score = loan_24m + 4 * loan_3m
```

- 관별로 최신·3개월 전·24개월 전 스냅샷을 보유하고 매월 갱신한다.
- 대출 데이터가 13개월 미만인 기관처럼 차분이 불가능한 입력은 별도 플래그와 감쇠 정책으로 처리한다.
- 누적 대출량은 L1 필터와 prior에는 사용하지만 `rank_score`의 주신호로 직접 사용하지 않는다.
- `book_demand_features`는 기준 월과 산출 버전을 함께 보존해 추천 결과를 재현할 수 있어야 한다.
- 운영 3개월 후 월별 스냅샷으로 전수 재검증하고, w=4가 계속 적절한지 확인한다.

## 5. 텍스트 보강과 추천 계산

텍스트 보강은 후보 필터가 아니라 후보 품질을 높이는 단계다.

1. 국중 URL에서 회수 가능한 텍스트를 API 호출 없이 먼저 확보한다.
2. 남은 후보는 수요순으로 카카오 보강 큐에 넣는다.
3. 정보나루 API는 승인 후 파일럿으로 품질과 비용을 검증한다.
4. 텍스트가 부족한 도서는 추천 후보에서 무조건 삭제하지 않고, 콘텐츠 기반 점수에 참여할 수 없는 상태로 표시한다.

추천 계산은 배치 영역에서 수행한다.

- 콜드스타트는 세그먼트 인기와 신간·수요 후보를 사용한다.
- 개인화는 `WISH`(좋아요), `READING`, `READ`, 평점, seed book, `BOOK_VIEW` 이벤트를 사용자 입력으로 사용한다.
- `BOOK_VIEW`는 도서 상세를 본 기록이며, 반복 조회·체류시간 같은 품질 신호가 쌓이기 전에는 낮은 가중치로만 반영한다. 단 한 번의 실수 클릭이 취향을 결정하지 않도록 unique 도서 수와 최근성으로 감쇠한다.
- 후보에서 이미 서재에 있는 도서를 제외한다.
- 콘텐츠 유사도와 수요 랭킹을 결합하되 수요 점수의 역할은 설정값으로 관리한다.
- 로그인 사용자의 새로 생성된 성공 결과만 `recommendations`와 `recommendation_items`에 저장한다. 같은 결과를 반환하는 모든 조회 요청을 새 행으로 저장하지 않는다.
- Spring Boot는 저장된 결과 조회, 서재 도서 제외 보정, 추천 이유 응답을 담당한다.
- 계산 실패 시 마지막 성공 결과 또는 콜드스타트 결과를 반환하며 검색·서재·인증과 장애 격리를 유지한다.

### 해시태그와 가중치를 결합하는 추천 기준

추천은 해시태그만으로 순위를 결정하지 않고, **해시태그를 취향·설명·검색의 공통 표현으로 사용한 뒤 기존 feature 가중치로 최종 순위를 계산**한다. 해시태그는 사람이 이해할 수 있는 결과를 만들고, 가중치는 데이터가 여러 개일 때 우선순위를 조절한다.

#### 책 단위 데이터와 태그

- 책 단위 수요 feature는 `book_demand_features`에 원값과 정규화 점수를 함께 저장한다. `trending_score`는 최근 3개월 대출량, `steady_score`는 최근 24개월 대출량을 0~100으로 정규화한 값이다.
- 책소개·목차·카테고리에서 추출한 콘텐츠 feature와 태그는 `book_content_features`에 배치로 저장한다.
- `#소설`, `#에세이`, `#과학`처럼 분류에서 직접 확인할 수 있는 태그와 `#판타지`, `#회귀물`, `#성장`, `#가벼운분위기`처럼 텍스트에서 추정하는 태그를 구분한다.
- 태그마다 `score`(0~100), `confidence`(0~1), `tag_version`을 기록한다. 판단할 수 없는 태그는 0이 아니라 `score = null`로 저장한다.
- 태그는 통제된 taxonomy로 관리한다. 외부 API가 반환한 임의 키워드를 그대로 공개 태그로 만들지 않으며, 원본 키워드와 서비스 태그의 매핑·출처를 추적한다.

초기 taxonomy는 다음 네 그룹으로 시작한다.

```text
분류:   #소설 #에세이 #과학 #역사 #경제
장르:   #판타지 #추리 #로맨스
소재:   #회귀물 #타임슬립 #성장 #가족
신호:   #지금뜨는 #스테디셀러 #신간 #내취향근접 #새로운분야
```

`#문체가쉬운책`, `#가벼운분위기`처럼 짧은 설명만으로 판단하기 어려운 태그는 낮은 confidence를 적용하고, 품질 검증 전에는 추천의 핵심 기준으로 사용하지 않는다.

#### 최종 feature와 가중치

- `taste`는 사용자가 선택하거나 높은 평점을 준 책의 태그·콘텐츠 feature·텍스트 벡터를 이용해 만든 사용자 취향과 후보 도서를 비교한 점수다.
- 후보 도서의 태그 일치도는 `taste` 계산에 반영한다. 태그 하나가 일치한다고 최종 순위를 확정하지 않는다.
- `coLoan`은 정보나루의 도서 간 함께 대출되는 신호일 뿐 사용자별 협업 필터링이 아니다. 데이터가 충분히 검증되기 전까지 낮은 가중치 또는 0으로 둔다.
- `newField`는 관심 분야 밖이지만 최소 유사도 기준을 통과한 도서와 신간성을 함께 고려하는 탐색 보정값으로 정의한다.
- 추천 계산 시 `taste`, `coLoan`, `trending`, `steady`, `newField`를 0~100으로 정규화하고 `weights`로 합산한다. 정보가 없는 feature는 가중치 분모에서 제외한다.

초기 기본 가중치는 설정값으로 관리하며 다음을 출발점으로 한다.

```text
taste      60
trending   15
steady     10
newField   15
coLoan      0
```

`coLoan`은 품질 검증 후 별도 실험으로 5 이하부터 조정한다. 위 수치는 최종 정답이 아니라 베타 측정 전의 안전한 기본값이며, 클릭·서재 등록·관심 없음 이벤트로 재평가한다.

#### 검색·화면·추천에서의 태그 사용

- Elasticsearch에는 정규화된 `tag_code`와 표시용 `tag_label`을 색인해 `#판타지` 같은 정확한 태그 검색을 지원한다.
- 서로 다른 태그 그룹은 기본적으로 AND로 묶고, 같은 그룹의 동의어·세부 태그는 OR로 확장한다. 예를 들어 `#판타지 #가벼운분위기`는 두 조건을 모두 만족하는 책을 우선한다.
- 추천 항목에는 설명용 `tags`와 계산 재현용 `featureScores`를 모두 반환한다. `#내취향근접`은 동적 추천 이유이고 `#판타지`는 책 콘텐츠 태그다.
- 로그인 추천 전체에는 당시 적용한 `weights`와 `appliedTags`를 함께 반환·저장한다. 사용자가 태그를 바꾸어도 기존 추천 스냅샷의 근거를 재현할 수 있어야 한다.

### 추천 결과 저장과 캐시 정책

#### DB에 저장하는 것

- 추천을 생성한 시점의 결과 묶음(`recommendations`)과 추천 도서별 순위·점수·이유(`recommendation_items`)를 저장한다.
- 이 저장 규칙은 로그인 사용자의 `COLD_START`·`PERSONALIZED` 결과에만 적용한다.
- `recommendationId`를 발급해 노출·클릭·이유 확인 이벤트와 연결한다.
- 저장 시점은 최초 생성, 사용자 평점·서재·초기 취향 변경 후 재생성, 정기 갱신처럼 결과가 실제로 새로 계산된 경우로 한정한다.
- 후보 전체, 계산 중간값, 동일 결과의 반복 조회 기록은 MVP DB에 저장하지 않는다.
- 최신 성공 결과와 이벤트 분석에 필요한 기간을 보존하고, 오래된 결과는 보관 기간 정책에 따라 정리한다.

#### 캐시에 저장하는 것

- Redis에는 `recommendation:v1:user:{userId}` 키로 최신 추천 응답 JSON을 저장한다.
- 캐시에는 `recommendationId`를 포함한 화면 응답 전체를 저장하며, TTL은 10~30분 범위의 설정값으로 둔다.
- 평점·서재·취향 변경 시 해당 사용자의 캐시를 즉시 무효화한다.
- 캐시 미스 또는 만료 시 DB의 최신 성공 결과를 조회하고, 없거나 오래됐을 때만 추천을 다시 계산한다.
- Redis는 성능 최적화 계층일 뿐 원천 데이터가 아니다. 캐시가 삭제되어도 DB 결과로 서비스가 동작해야 한다.

브라우저의 TanStack Query 캐시는 화면 이동과 재요청을 줄이는 클라이언트 캐시로만 사용한다. 로그인 추천은 새로고침 후에도 결과·`recommendationId`·이벤트 연결을 유지해야 하므로 DB 스냅샷을 기준으로 한다.

### 감상평의 MVP 정책

- 사용자는 도서별 별점과 함께 선택적으로 한 줄 감상평을 기록할 수 있다.
- 감상평은 `book_ratings.review_text`에 저장하며, 본인만 조회·수정할 수 있다.
- MVP에서는 감상평을 추천 점수, 검색 색인, BOOK DNA, 임베딩에 사용하지 않는다.
- 감상평 원문은 삭제하지 않는 한 보존하되, 다음 버전에서 AI 활용 여부·사용자 동의·분석 범위를 별도로 확정한다.

## 6. MVP에서 보류하는 기능

- 근처 도서관 검색·보유 여부 조회는 MVP에서 제공하지 않는다.
- `libraries`와 `library_holding_snapshots`는 현재 운영 ERD와 ERDCloud import DDL에 포함하지 않는다.
- 대출 원장은 추천 수요 feature 산출에 필요한 배치 입력으로만 사용한다.
- 추후 기능을 도입할 때 도서관 내부 ID·API `libCode`·좌표·복본 수를 별도 스키마로 재검토한다.

## 7. 서비스 API 방향

| 기능 | 동작 방향 |
| --- | --- |
| 도서 검색 | L0 전체를 대상으로 제목·저자 검색. 결과가 없고 ISBN이 있으면 온디맨드 등록 시도 |
| 도서 상세 | canonical 도서 정보와 로그인 사용자의 서재 상태·평점·본인 감상평 제공 |
| 찜 | 별도 Like 없이 `WISH` 서재 등록 |
| 평점·감상평 | 별점은 MVP 추천 신호, 감상평은 개인 기록 전용 |
| 추천 | 로그인 사용자는 콜드스타트 또는 최신 개인화 결과를 조회한다. Redis 캐시가 있으면 우선 반환하고 로그인 사용자의 서재 도서는 제외 |
| 추천 이유 | `tags`, `reasonType`, `reasonText`를 추천 항목에 저장해 결과와 함께 반환 |
| 추천 기준 조절 | 관심 태그는 `appliedTags`로 표시하고, 최종 랭킹은 `weights`로 조절 |

추천 화면은 데이터 수집·텍스트 보강·추천 배치가 지연되어도 검색·상세·서재를 사용할 수 있어야 한다.

## 8. 단계별 구현 순서

1. L0 국중·정보나루 ISBN13 합집합 정제 및 `books`/`book_source_records` 적재
2. 외부 대출 원장의 최신·3개월 전·24개월 전 스냅샷 확보 및 차분 검증
3. 수요 99% 임계와 신간 트랙을 적용한 `book_demand_features` 생성
4. 책소개·목차·카테고리 기반 콘텐츠 feature·통제 태그 추출 및 품질 검증
5. 제목·저자·책소개·태그 색인 및 L0 검색·온디맨드 등록 구현
6. 로그인 콜드스타트 추천 → 조회·좋아요·평점 기반 개인화 추천 → 가중치 재정렬 → 추천 결과 저장
7. 추천 태그·이유와 이벤트 측정 연동

## 9. 아직 확정하지 않는 사항

- 카카오 `contents` 확보율과 보강 비용
- 정보나루 API 승인 후 실제 품질·호출 제한
- PK 타입과 분석 원장의 물리적 저장소
- 외서·전자책·학술서의 별도 타깃 정책
- 추천 수요 점수와 콘텐츠 점수의 최종 블렌드 가중치
- 감상평을 AI 분석에 사용할지 여부와 사용자 동의·비공개 정책
