# 임베딩 텍스트 소스 비교 — 사전 등록 프로토콜

**작성 2026-08-27. 결과를 보기 전에 확정한다.**
결과가 나온 뒤 이 문서를 고치지 않는다. 고쳐야 할 이유가 생기면 그 사실 자체를 기록한다.

<br/>

## 1. 답하려는 질문

> 임베딩 입력으로 **정보나루 소개문 / 카카오 소개문 / 둘을 이어붙인 것** 중
> 어느 쪽이 추천 품질이 가장 높은가?

부수 질문 — 텍스트가 **주제 신호를 실제로 담고 있는가.**
담고 있지 않다면 어느 소스를 쓰든 무의미하고, 임베딩 기반 추천 자체를 재검토해야 한다.

<br/>

## 2. 왜 이 실험이 필요한가

앞선 측정([본문 품질 비교](#))에서 두 소스가 **어휘 수준에서 거의 겹치지 않는다**는 것을 확인했다.

| | 정보나루 | 카카오 |
| --- | ---: | ---: |
| 중앙 길이 | 145자 | 251자 |
| 문장 중간 절단 | 0.5% | 84.5% |
| 6-gram 포함률 중앙 | \multicolumn{2}{c}{0.06 — 65.9%가 거의 다른 문장} |

카카오가 더 길지만 250자에서 잘리고, 정보나루는 짧지만 완결돼 있다.
성격도 다르다 — **카카오는 줄거리, 정보나루는 작품의 위치·의의**를 준다.

"어느 쪽이 더 좋은가"는 텍스트의 겉모습만으로는 답이 안 나온다. 실제로 벡터를 만들어 재야 한다.

<br/>

## 3. 실험군

같은 책 집합에 대해 **텍스트 구성만 바꾼다.** 모델·전처리·평가 절차는 전부 동일하다.

| 군 | 임베딩 입력 |
| --- | --- |
| **D** | 정보나루 `description` 단독 |
| **K** | 카카오 `contents` 단독 |
| **D+K** | 정보나루 + 카카오 이어붙임 |
| **K+D** | 카카오 + 정보나루 이어붙임 (순서 효과 확인용) |

<br/>

## 4. 표본

- 정보나루와 카카오가 **둘 다 100자 이상**인 책만 쓴다.
  한쪽만 있는 책을 섞으면 커버리지 차이가 품질 차이로 둔갑한다.
- 목표 **10,000건**. 확보되는 만큼 쓰되 최소 3,000건 미만이면 판정을 보류한다.
- 두 수집기가 같은 우선순위 큐를 쓰므로 앞부분이 그대로 겹친다.

<br/>

## 5. 평가 방법 — 텍스트가 모르는 것을 맞히게 한다

임베딩 입력에 **제목·저자·출판사·KDC 를 넣지 않는다.** 소개문 본문만 넣는다.
그리고 그 벡터가 **본문에 없는 메타데이터를 맞히는지** 본다.

> 제목이나 KDC 를 입력에 넣으면 그 문자열끼리 매칭돼 점수가 부풀려진다.
> 본문만 넣어야 "이 텍스트가 주제 신호를 담고 있는가" 를 잰 것이 된다.

### 주 지표 — KDC-3 정밀도@10

각 책을 질의로 삼아 최근접 10건(자기 자신 제외)을 뽑고,
그중 **질의와 KDC 3자리가 같은 책의 비율**을 잰다. 전체 책에 대해 평균한다.

KDC 는 사서가 매긴 분류이고 본문에 적혀 있지 않다.
따라서 이 지표가 높다는 것은 **텍스트만으로 주제를 복원했다**는 뜻이다.

### 보조 지표

| 지표 | 의미 |
| --- | --- |
| KDC-1 정밀도@10 | 대분류 수준. 거친 주제 판별력 |
| 저자 정밀도@10 | 같은 저자를 찾아내는가 |
| 삼중항 정확도 | 같은 KDC-3 인 책이 다른 KDC-1 인 책보다 가까운가 |

> **저자 지표에는 누출이 있다.** 두 소스 모두 본문에 저자명을 언급하는 일이 잦다.
> 다만 누출은 모든 군에 공통이므로 군 간 비교로는 여전히 쓸 수 있다.
> 절대값을 "저자 판별력" 으로 읽지 않는다.

### 기준선

| 기준선 | 목적 |
| --- | --- |
| 무작위 | KDC-3 분포에서 무작위로 10건 뽑았을 때의 기대 정밀도 |
| 제목만 | 소개문 없이 제목만 임베딩. **소개문이 제목 이상을 주는지** 확인 |

<br/>

## 6. 판정 규칙 — 결과를 보기 전에 정한다

1. **주 지표(KDC-3 정밀도@10)로만 순위를 정한다.** 보조 지표로 순위를 뒤집지 않는다.
2. **잡음 측정** — 표본을 무작위 절반으로 나눠 각각 측정하고, 두 값의 차이를 잡음 폭으로 삼는다.
   군 간 차이가 이 잡음 폭보다 작으면 **동률로 판정**한다.
3. 동률이면 **더 싼 쪽**을 택한다. 비용 순서: D (수집 완료분 재사용) < K < D+K.
4. 어느 군도 "제목만" 기준선을 넘지 못하면 **소개문 임베딩 전략 자체를 재검토**한다.

<br/>

## 7. 모델

- 한국어 문장 임베딩 모델 1종을 고정한다. 파라미터 6억 이하 (RTX 4070 6GB 제약).
- 후보: `jhgan/ko-sroberta-multitask`, `BM-K/KoSimCSE-roberta`, `intfloat/multilingual-e5-base`
- **모델은 하나만 쓴다.** 여러 모델을 돌려 좋은 결과를 고르면 그건 실험이 아니다.
  모델 선택이 결과를 바꾸는지는 별도 확인 사항으로 남긴다.

<br/>

## 8. 미리 밝혀두는 한계

- **KDC 일치가 곧 좋은 추천은 아니다.** 같은 분류 안에서도 취향은 갈린다.
  이 실험은 "텍스트가 주제를 담는가" 까지만 답한다.
- 사용자 행동 데이터가 없어 **실제 추천 만족도는 측정할 수 없다.**
  그것은 서비스 운영 후 클릭·찜 로그로만 답이 난다.
- 표본이 수요 상위 구간에 치우쳐 있다. 꼬리 구간은 텍스트가 짧고 부실해
  **여기서 나온 수치는 상한으로 읽어야 한다.**
