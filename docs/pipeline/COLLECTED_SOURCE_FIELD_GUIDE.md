# 수집 원본 데이터 필드 가이드

> 대상: 국립중앙도서관 ISBN 서지 원본과 정보나루 `usageAnalysisList` 수집본
>
> 기준일: 2026-08-31. 정보나루 수집은 진행 중이므로 행 수와 채움률은 계속 변한다.

이 문서는 **현재 실제 파일에서 확인한 컬럼**을 기준으로, 각 데이터가 무엇을 뜻하고
서비스·추천에서 어떻게 써야 하는지를 정리한다. 원본값은 재처리와 출처 검증을 위해
`project_personal/`에 보존하고, 서비스 DB에는 정규화·검증된 값을 적재한다.

## 1. 파일과 역할

| 출처 | 실제 파일 | 현재 규모 | 핵심 역할 |
| --- | --- | ---: | --- |
| 국립중앙도서관 | `nl_books.parquet` | 2,047,239행 | ISBN 판본 기준의 마스터 서지. 모든 소스 결합의 기준 |
| 정보나루 | `data4library/d4l_usage.jsonl` | 55,041행 이상, 수집 중 | 책소개·키워드·함께대출·월별 대출·인구통계 보강 |

모든 소스의 표준 결합축은 **정규화한 ISBN13 문자열**이다.

```text
국중 EA_ISBN ── 정규화 ──> isbn13
정보나루 isbn13 ─────────> isbn13
대출 원장 isbn13 ─────────> isbn13
카카오 isbn13 ───────────> isbn13
```

ISBN은 숫자가 아니라 문자열로 저장한다. 하이픈·공백 제거, 체크섬 검증, ISBN10→13 변환 후에만
canonical 도서와 결합한다.

## 2. 국립중앙도서관 원본 필드

원본 파일의 39개 컬럼은 모두 `VARCHAR`다. 이는 ISBN의 선행 숫자와 원문 표현을 보존하기 위한
의도적 선택이다. 빈 문자열은 정규화 단계에서 `NULL`로 바꾸되 원본에는 남긴다.

### 2.1 식별자와 판본·세트 관계

| 원본 컬럼 | 의미 | 정제/저장 방침 | 활용 |
| --- | --- | --- | --- |
| `EA_ISBN` | 개별 판본 ISBN. ISBN10·13 혼재 | `isbn_raw`, `isbn10`, `isbn13`, 검증 상태로 분리 | **도서 PK 후보·모든 외부 JOIN** |
| `SET_ISBN` | 세트 ISBN | 유효 ISBN이면 별도 보조키 보존 | 세트·낱권 관계 |
| `RELATED_ISBN` | 관련 도서 ISBN | 복수 값 분리 가능성을 고려해 원문 보존 | 관련 판본 후보 |
| `CONTROL_NO` | 국중도 제어번호 | 원문 보존 | ISBN 부재 시 보조 식별자 |
| `EDITION_STMT` | 판차·개정판 표현 | 원문 보존·필요 시 파싱 | 판본 구분 |
| `SERIES_TITLE` | 총서명 | 문자열 정규화 | 시리즈 표시·중복 제어 보조 |
| `SERIES_NO` | 총서 내 순번 | 원문 보존 | 시리즈 순서 |
| `VOL` | 권차 | 숫자/문자 혼재이므로 원문 보존 | 다권본·시리즈 중복 방지 |
| `SET_EXPRESSION` | 세트 구성 자유 표현 | 원문 보존 | 세트 표시·관계 후보 |

`TITLE`과 저자가 같아도 ISBN이 다르면 다른 판본이다. 시리즈·개정판 관계는 별도로 관리하며,
제목만으로 canonical 도서를 병합하지 않는다.

### 2.2 기본 서지와 검색 필드

| 원본 컬럼 | 의미 | 정제/저장 방침 | 활용 |
| --- | --- | --- | --- |
| `TITLE` | 도서 제목 | 원문 보존, 검색용 정규화값 별도 생성 | **검색·상세·추천 표시 핵심** |
| `AUTHOR` | 저자 원문. 지음·옮김·편 등 역할어 포함 | `author_raw` 보존, 화면/검색용 저자 배열 파생 | 검색·작가 선호 |
| `PUBLISHER` | 출판사 | 공백·placeholder 정리 | 상세 표시·판본 구분 |
| `PUBLISHER_URL` | 출판사 관련 URL | 접근 가능성 검증 후 보조 보관 | 외부 링크, 추천 입력 아님 |
| `FORM` | 발행·제본 형태 | 표준 형태 코드로 매핑 가능 | 종이책·전자책 등 필터 |
| `FORM_DETAIL` | 형태 상세 | 원문 보존 | 상세 표시·형태 보조 |
| `BOOK_SIZE` | 판형 | 원문 보존 | 상세 표시, 초기 추천 비사용 |
| `EBOOK_YN` | 전자책 여부 | `Y/N` 검증 | 판본·노출 정책 |

### 2.3 날짜와 수집 이력

| 원본 컬럼 | 의미 | 정제/저장 방침 | 활용 |
| --- | --- | --- | --- |
| `PUBLISH_PREDATE` | 발행예정일, 보통 `YYYYMMDD` | 날짜·미래 이상값 검증, `planned_published_date`로 저장 | 신간 후보의 보조 기준 |
| `REAL_PUBLISH_DATE` | 실제 발행일 후보 | 값이 있을 때만 날짜 검증 | 실제 출간일 후보 |
| `INPUT_DATE` | 국중도 등록일 | `source_input_date`로 보관 | 증분 수집 기준 |
| `UPDATE_DATE` | 국중도 수정일 | `source_updated_date`로 보관 | 변경 감지·재적재 |

`PUBLISH_PREDATE`는 결측이 적지만 실제 출간일이 아니다. 미래 날짜·비정상 날짜가 있으므로
검증 없이 신간성 점수에 사용하지 않는다.

### 2.4 분류와 독자 대상

| 원본 컬럼 | 의미 | 정제/저장 방침 | 활용 |
| --- | --- | --- | --- |
| `EA_ADD_CODE` | 5자리 부가기호: 독자대상 1자리 + 발행형태 1자리 + 내용분류 3자리 | 숫자로 변환하지 않고 문자열 유지, 세 부분 파생 | **태그·독자대상·형태·내용분류 feature** |
| `SET_ADD_CODE` | 세트 부가기호 | 원문 보존 | 세트 보조 정보 |
| `SUBJECT` | 주제 대분류 코드 | 코드표 매핑 | **초기 장르·주제 태그** |
| `KDC` | 한국십진분류 | 결측이 많아 보조 분류로 사용 | 세부 분류·태그 보강 |
| `DDC` | 듀이십진분류 | 결측이 많아 보조 보관 | 외서/세부 분류 보조 |

`EA_ADD_CODE`는 앞자리에 `0`이 올 수 있다. `03230` 같은 값을 숫자로 바꾸면 정보가 손상된다.

### 2.5 텍스트와 URL

| 원본 컬럼 | 의미 | 정제/저장 방침 | 활용 |
| --- | --- | --- | --- |
| `BOOK_INTRODUCTION` | 책소개 본문 | 원문과 정제본 분리 | 임베딩 보조 입력 |
| `BOOK_INTRODUCTION_URL` | 책소개 파일 URL | 텍스트 URL을 회수, 이미지 URL은 별도 처리 | 소개문 보강 |
| `BOOK_TB_CNT` | 목차 본문 | 원문·정제본 분리 | **임베딩의 풍부한 입력** |
| `BOOK_TB_CNT_URL` | 목차 파일 URL | 텍스트 회수 | 목차 보강 |
| `BOOK_SUMMARY` | 요약 본문 | 원문·정제본 분리 | 임베딩 보조 입력 |
| `BOOK_SUMMARY_URL` | 요약 파일 URL | 텍스트 회수 | 요약 보강 |
| `TITLE_URL` | 표지·제목 관련 URL | 이미지 URL 접근성 확인 | 표지 fallback |

국중도 텍스트 본문은 결측이 크다. 텍스트 URL 회수분은 `nl_text_clean.csv`의 별도 정제본으로
관리하며, `books.description` 하나에 덮어쓰지 않는다.

### 2.6 가격과 물리 정보

| 원본 컬럼 | 의미 | 정제/저장 방침 | 활용 |
| --- | --- | --- | --- |
| `PRE_PRICE` | 정가 원문 | 숫자 파싱 성공값만 별도 저장 | 화면 표시 보조 |
| `REAL_PRICE` | 실제 판매가 원문 | 숫자 파싱 성공값만 별도 저장 | 화면 표시 보조 |
| `PAGE` | 쪽수 자유 표현 | 원문 보존, 확실한 숫자만 `page_count` | 분량 선호 보조 |

가격은 사용자 가격 민감도 데이터가 생기기 전까지 추천 핵심 점수에 넣지 않는다. `PAGE`가 없는
도서도 추천에서 탈락시키지 않고 해당 feature만 제외한다.

### 2.7 서지 상태 플래그

| 원본 컬럼 | 의미 | 정제/저장 방침 | 활용 |
| --- | --- | --- | --- |

| `DEPOSIT_YN` | 납본 여부 | 원문 보존 | 수집 상태 분석 |

이 플래그들은 취향을 뜻하지 않으므로 추천 feature로 직접 사용하지 않는다.

## 3. 정보나루 현재 수집 필드

수집기는 `usageAnalysisList`를 ISBN13당 한 번 호출한다. API 원문 전체는 별도 보관하고,
`d4l_usage.jsonl`에는 추천에 필요한 값을 경량화해 기록한다. 성공 레코드에 없는 빈 값은 파일
크기를 줄이기 위해 생략될 수 있으므로, **필드 부재는 값 없음**으로 읽는다.

### 3.1 기본 서지와 분류

| 컬럼 | 타입 | 의미 | 서비스·추천 활용 |
| --- | --- | --- | --- |
| `isbn13` | `VARCHAR` | 조회 기준이자 정규화 ISBN13 | **국중·대출·카카오 JOIN 키** |
| `ok` | `BOOLEAN` | 수집 성공 여부 | 실패·미수록·재시도 관리 |
| `bookname` | `VARCHAR` | 정보나루 제목 | 국중 미수록 도서의 제목 fallback |
| `authors` | `VARCHAR` | 저자 원문 | 국중 미수록 도서의 저자 fallback |
| `publisher` | `VARCHAR` | 출판사 | canonical 서지 보강 |
| `pub_year` | `VARCHAR` | 발행 연도 | 신간·표시 보조. 날짜가 아니라 연도 |
| `class_no` | `VARCHAR` | KDC 계열 분류번호 | **세부 분류·태그 보강** |
| `class_nm` | `VARCHAR` | 분류의 자연어 경로 | 화면·태그 매핑 보조 |
| `add_symbol` | `VARCHAR` | 정보나루 부가기호 | 독자대상·형태·내용분류 보강 |
| `vol` | `VARCHAR` | 권차 | 시리즈·판본 중복 제어 보조 |
| `img` | `VARCHAR` | 표지 URL | 표지 후보 |

국중도와 같은 ISBN이 있으면 국중도는 기준 서지로 유지하고, 정보나루 값은 결측 보강 또는
출처별 값으로 보존한다. 국중도에 없는 ISBN은 정보나루 서지가 canonical 도서 후보가 된다.

### 3.2 설명문과 키워드

| 컬럼 | 타입 | 의미 | 서비스·추천 활용 |
| --- | --- | --- | --- |
| `desc` | `VARCHAR` | 출판사 제공 책소개 | **텍스트 임베딩의 주 입력** |
| `desc_len` | `BIGINT` | `desc` 문자 수 | 100자 미만 제외·품질 판정 |
| `keywords` | `VARCHAR[][]` | 최대 50개 `[단어, 가중치]` 쌍 | 정제 후 임베딩 보조·분류 보조 |

`keywords`는 통제 태그가 아니다. 저자·출판사·제목이 섞일 수 있으므로, 그대로 사용자에게
`#태그`로 노출하지 않는다. 서지어를 제거한 뒤 임베딩 입력 또는 태그 추출의 보조 재료로 쓴다.

`desc`는 `book_text_documents` 같은 출처·텍스트 유형별 테이블에 저장하고, 카카오·국중도
텍스트와 함께 임베딩 입력 조합을 만든다.

### 3.3 대출 수요와 관계 추천 신호

| 컬럼 | 타입 | 구조 | 활용 |
| --- | --- | --- | --- |
| `loan_total` | `BIGINT` | 누적 대출 수 | 후보 우선순위·수요 prior. 랭킹 주신호로 직접 사용하지 않음 |
| `co_loan` | `VARCHAR[][]` | 함께 대출된 책 목록 | **도서 간 관계 추천의 주 신호** |
| `mania_rec` | `VARCHAR[][]` | 마니아 이용자 추천 목록 | 보조 관계 후보 |
| `reader_rec` | `VARCHAR[][]` | 다독자 추천 목록 | 보조 관계 후보 |
| `loan_history` | `JSON[][]` | `[연월, 대출수, 전국순위]`의 월별 이력 | 추세·랭킹 feature 입력 |
| `loan_grps` | `JSON[][]` | `[연령, 성별, 대출수, 순위]` 교차 분포 | 콜드스타트 세그먼트 보조 |

`co_loan`, `mania_rec`, `reader_rec`는 JSON 배열로만 두지 말고, ETL에서
`book_relation_edges` 행으로 풀어 저장한다. 대상 ISBN이 아직 canonical 도서에 없어도
`target_isbn13`을 먼저 보존하고 나중에 `target_book_id`를 연결한다.

`loan_history`의 대출값은 누적 스톡일 수 있다. 최근성 점수는 원값이 아니라 월별 차분,
동시기 전체 대비 백분위, 계절성 보정을 거쳐 산출한다.

### 3.4 정보나루 중첩 배열의 값 구조

| 컬럼 | 원소 구조 | 비고 |
| --- | --- | --- |
| `keywords` | `[word, weight]` | `weight`는 API가 준 키워드 가중치 |
| `co_loan` | 도서 목록의 주요 서지값 배열 | 같은 이용자가 함께 빌린 item-item 신호 |
| `mania_rec` | 도서 목록의 주요 서지값 배열 | 마니아 이용자 기반 추천 |
| `reader_rec` | 도서 목록의 주요 서지값 배열 | 다독자 기반 추천 |
| `loan_history` | `[month, loanCnt, ranking]` | 보통 월별 12개월 이력 |
| `loan_grps` | `[age, gender, loanCnt, ranking]` | 연령×성별 분포 |

## 4. 결측치 현황과 처리 기준

아래는 **2026-08-31 집계 시점**의 결측치다. 문자열은 `NULL` 또는 공백, 배열은 `NULL` 또는
빈 배열을 결측으로 계산했다. 정보나루는 수집이 진행 중이므로 이후 다시 계산해야 한다.
`0.0%`는 반올림 결과이며, 실제 결측이 없다는 뜻은 아닐 수 있다.

### 4.1 국립중앙도서관 (`2,047,239`행)

| 필드 | 결측 건수 | 결측률 | 해석·처리 |
| --- | ---: | ---: | --- |
| `EA_ISBN` | 25,594 | 1.3% | canonical ISBN을 만들 수 없으므로 보조 식별자 매칭 또는 제외 |

### 4.3 공통 규칙

1. 결측은 기본값 `0`, 빈 문자열, `미상`으로 치환하지 않고 `NULL`과 결측 사유로 보존한다.
2. 추천 점수는 사용 가능한 feature만으로 가중치를 재정규화한다. `loan_history`가 없다고 인기 0점으로 감점하지 않는다.
3. `text_missing`, `text_too_short`, `api_not_provided`, `api_request_failed`, `isbn_invalid`처럼 **결측 사유**를 분리한다.
4. 필수 후보 조건은 ISBN13 유효 + 제목 존재로 최소화한다. 소개문·KDC·대출통계 결측은 후보 탈락 사유가 아니다.
5. 배치 실행마다 전체 행 수·컬럼별 결측률·`ok=false` 수를 `ingestion_runs` 품질 지표로 남긴다.

## 5. 추천용 데이터 흐름

```text
[국중도]
EA_ISBN, TITLE, AUTHOR, SUBJECT, EA_ADD_CODE, URL 텍스트
     │ ISBN13 정규화·서지 검증
     ▼
books / book_source_records / book_text_documents
     ▲
     │ ISBN13 JOIN
[정보나루]
bookname, desc, keywords, co_loan, loan_history, loan_grps
     ├─ description·keywords → book_text_documents → embedding_profiles → Qdrant
     ├─ co_loan·mania_rec·reader_rec → book_relation_edges
     ├─ loan_total·loan_history → book_demand_features
     └─ class_no·add_symbol → book_tags / content feature 보강
```

## 6. 저장 원칙 요약

1. 원본 데이터는 덮어쓰지 않는다. 정규화·정제·임베딩 산출물은 별도로 만든다.
2. ISBN13은 문자열로 검증·정규화한 뒤 결합한다.
3. 국중도는 판본·기본 서지의 기준이고, 정보나루는 설명·수요·관계 신호의 주 보강원이다.
4. `desc`·목차·요약·키워드는 출처와 유형을 보존한 텍스트 행으로 관리한다.
5. 대출 원장 전체와 원본 JSON은 서비스 DB에 넣지 않는다. 추천에 필요한 파생 feature만 적재한다.
6. 결측 feature는 0점이 아니라 `NULL`로 다루고, 최종 추천 점수에서 가중치를 재정규화한다.
7. 정보나루 수집의 `ok=false`는 단순 "책 없음"으로 즉시 확정하지 않는다. 쿼터·연속 실패·네트워크 오류와 구분해 재시도한다.
