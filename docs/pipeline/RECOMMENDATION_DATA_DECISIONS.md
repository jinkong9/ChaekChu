## 2. 결정 1 — 마스터 카탈로그는 국중 단독이 아니라 합집합

### 결정
카탈로그(L0) = 국중 ∪ 정보나루 ≈ 300만 건. 조회(검색·찜) 표면은 여기서 서빙하고,
미등재 ISBN 검색 시 카카오 1회 호출로 즉시 등록(온디맨드)한다.

### 근거 (실측)
1. **국중 단독이면 대출량의 27.6%를 버린다.** 250개관 실측에서 미매칭 한국서가
   대출량의 23.0%(1.25억 건), 외서가 4.6%를 차지했다.
2. **수요 최상위가 더 뚫려 있다.** 대출량 상위 0.1%(2,119권)의 국중 매칭률이
   67.7% — 가장 많이 빌려간 책 1,000권 중 320권이 국중에 없다.
3. **미매칭의 70%는 구조적으로 해결 불가다.** 외서(국중은 한국 ISBN 등록처, 미매칭율
   99.9~100%)와 2006년 이전 한국서(국중 서지 DB가 소급 미등록, 2007년 기점으로
   미매칭율 40%→15% 급락)가 원인이며, ISBN 형식 문제는 0.08%로 배제됐다
   (240건 카카오 짝비교 불일치 0건).
4. **합집합의 추가 비용이 0이다.** 정보나루 CSV가 도서명·저자·출판사·발행년도·
   소수점 KDC(채움율 98%+)를 자체 보유하므로 서지가 이미 손에 있다.

### 기각한 대안
- *국중 단독 유지*: 위 1·2로 정합성 주장 불가.
- *제목 매칭으로 미매칭 회수*: 저자 일치까지 요구 시 15.5%만 회수되고 텍스트 확보는
  0.9%뿐. 제목만 매칭은 후보 최대 1,019개 오병합 덩어리라 기각.

## 3. 결정 2 — 필터는 "누적 대출, 수요 99% 유지" 임계

### 결정
L1 후보 = 누적 대출 상위 "전체 대출량의 99%를 유지하는 최대 임계".
1,660개관 전수 합산 기준 **임계 72+, 후보 948,537건, 카카오 32일**.
여기에 신간(국중 2025+ 중 도서관 미유입 103,318건)을 무조건 합류.

### 근거 (실측)
1. **곡선이 절벽이 아니라 평지→무릎 구조다.** 임계 스윕(250개관)에서 구간당 수요
   손실이 임계 20까지 ≤0.23%p, 30부터 0.45→0.9→1.1%p로 가속했다.
   임계 선택은 "마법의 숫자"가 아니라 평지 위의 선택이며, 10~30 어디를 골라도
   수요 커버가 99.7~98.8% 안에서 움직인다 — 이 둔감성이 신뢰도의 실체다.
2. **절대값 임계는 규모에 오염된다.** 같은 "20+"가 250개관에서는 수요 99.2%,
   1,660개관에서는 훨씬 느슨한 기준이 된다 (전수 합산의 99% 지점은 72+).
   "수요 99%"로 정의하면 규모가 변해도 스펙이 자동 적응한다.
3. **필터가 누적이어야 하는 이유는 오류 비용의 비대칭이다.** 잘못 넣은 후보는
   랭킹이 밑으로 내리므로 비용이 거의 없다. 잘못 뺀 후보는 영원히 추천 불가다.
   느린 스테디셀러(전국 연 7회 수준)는 2년 창 임계에서 잘리지만 누적에서 살아남는다.
4. **수요 집중이 극단적이라 보강 비용이 감당된다.** 상위 6만 권 = 대출량 50%,
   37만 권 = 90%. 수요순 보강 큐로 카카오 12일 만에 노출 가중 90%를 채운다.
5. **"대출 1건 이상"은 필터로 무력하다.** 약 10년 누적이라 장서의 84.2%가 통과한다.

### 기각한 대안
- *국중 텍스트 보유 여부로 필터*: 전략 문서 §4.1이 경고한 인기 편향을 데이터 층에서
  구워 넣는 짓이다. 또한 대출 필터를 조일수록 국중 텍스트 보유율이 오히려 떨어진다
  (7.0%→5.2%) — 텍스트 확보는 필터가 아니라 보강의 일이다.
- *최근 1년 창으로 필터*: 단일 관 기준 누적 20+ 통과 도서의 56.4%가 최근 1년 휴면 —
  그러나 이는 1개관 관측이고, 관 횡단 합산에서는 완화된다. 재현율 손실이 더 크다.

## 4. 결정 3 — 랭킹은 "직전 2년 차분 + 4×모멘텀", 누적 금지

### 결정
인기 신호 = (최신 누적 − 24개월 전 누적) + 4 × (최신 누적 − 3개월 전 누적).
관당 스냅샷 3개(최신 / −3개월 / −24개월)로 매월 갱신. 누적값은 랭킹 주신호로 쓰지 않는다.

### 근거 — 사전 등록 실험 (2026-08-26)
결과를 보기 전에 프로토콜을 고정했다: 층화 45개관(3분위×15, 시드 20260825) 합산,
**2-fold 분리**(Fold A에서 블렌드 가중치 w 튜닝, Fold B에서만 판정 — 과적합 차단),
주지표 = **수요가중 재현율@1000**(예측 상위 1,000권이 실제 미래 대출량의 몇 %를
담는가 — 보강 큐·랭킹의 실목적에 가장 가까운 지표), 동률 기준 = 표본 반분 재현성.

Fold B (판정 전용, 모집단 773,753권 / 타깃 대출 381,066건):

| 예측자 | ρ | top1000 겹침 | 수요재현@1000 |
| --- | --- | --- | --- |
| 모멘텀 3개월 | 0.566 | 76% | 14.9% |
| 직전 1년 | 0.560 | 78% | 15.3% |
| **직전 2년** | 0.538 | 78% | **15.3%** |
| **누적** | 0.389 | **26%** | **7.1%** |
| **blend(w=4)** | 0.554 | **79%** | **15.4%** |

판정 (동률 기준 ±0.9%p, 사전 등록 규칙):
- **R1** y1 = y2 동률 → 규칙대로 **2년 채택** (안정성 우위, 비용 동일)
- **R2** blend가 y2와 동률 → **유지** (비용 0, Fold A가 독립적으로 w=4 선택)
- **R3** 누적이 압도적 최하위 (격차가 노이즈의 9배) → **부적합 확정**

### 누적이 랭킹에 부적합한 이유 — 4회 독립 확인
1. 단일 관: 누적 20+ 통과 도서의 56.4%가 최근 1년 휴면 (누적 694건/최근 0건 사례)
2. 단일 관: 누적 상위 1000 vs 최근 상위 1000 겹침 26.8%
3. 2개관 장·단기 실험: 누적 top100 겹침 3~5%
4. 45개관 사전 등록 실험: 수요재현 7.1% vs 15.4% (위 표)

구조적 원인: ① 누적은 오래된 책에 시간 이점이 있다 ② 관마다 누적 창이 60~120개월로
달라 합산이 왜곡된다(1년/2년 차분은 창을 통일한다) ③ 취향은 이동한다.

### 모멘텀을 넣는 이유
합산 top100에서 모멘텀 단독이 최강(48%, 2개관 실험) — **랭킹 최상위일수록 "지금
뜨는가"가 이긴다.** 블렌드는 몸통(창의 안정성)과 머리(모멘텀의 신선도)를 합친다.
운영에서는 정보나루 `hotTrend`(주간 급상승, API 승인 후)와 자체 로그가 실시간 트렌드를 보강한다.

### 실험의 신뢰 근거와 한계
- 규모 효과 확인: 2개관 → 45개관에서 top1000 겹침 41~49% → 74~79%, ρ 0.34 → 0.54.
  절대 수치의 상당 부분은 소규모 카운트 노이즈였고, 전수 운영에서는 더 높아진다.
- 낮아 보이는 절대값(수요재현 15%)의 해석: 타깃이 "다음 3개월"이라 신간·이벤트성
  수요(드라마화·수상 등)는 어떤 과거 창도 못 맞춘다. 이 몫은 창이 아니라
  트렌드 신호·신간 트랙의 담당이다. 시스템은 매월 갱신되므로 실전 신선도는 1개월이다.
- 한계: 단일 계절 fold(1~4월 튜닝 / 4~7월 판정), 신간 제외 모집단, w는 {2,4,8}만 탐색.
  **운영 3개월 후 월별 스냅샷이 쌓이면 전수 1,660개관 백테스트가 추가 비용 0으로
  가능하다 — 그때 재검증한다 (120개관 표본 재실행은 불필요 판정).**

## 5. 결정 4 — 보유 원장 스키마 (근처 도서관 기능)

### 결정
ISBN 합산만 저장하지 않고 **관별 원장을 1급 데이터로 유지**한다.

```
libraries.parquet      lib_id(내부) · api_libcode(정보나루 API) · 이름 · 유형
                       · 주소 · 위도 · 경도 · 전화 · 최신월     (1,660행)
holdings.parquet       lib_id × isbn13(정규화) × 대출 × 도서권수  (121,135,896행, 673MB)
books_dedup.parquet    ISBN 단위 + 서지·KDC + lib_count          (2,953,587행 — 파생)
```

### 근거
1. "이 책을 보유한 근처 도서관" 조회가 조인 한 번으로 끝난다. 검증 완료:
   해리포터 『불의 잔』 → 양산시립중앙(대출 4,884·28권·좌표) 등 즉시 반환.
2. **ID가 두 체계다.** 사이트 내부 id(29981)와 API libCode(127058)가 다르며,
   `bookExist`·`libSrchByBook` API와 위경도는 libCode에 붙는다. 둘 다 보존해야 한다.
3. `도서권수`는 복본 수 = "빌릴 수 있을 확률"의 재료이자 보조 인기 신호다.
4. 합산(books_dedup)은 원장에서 언제든 재생성 가능한 파생물이다. 역방향은 불가능
   하므로 원장이 원본이어야 한다.

### 데이터 정제 (빌드 단계 내장)
- ISBN 체크숫자 오류 폴백: 도서관 데이터의 "978+ISBN10 체크숫자 미재계산" 오류
  (0.26% 실측)를 앞 12자리 재계산으로 회수
- 한국 상품 EAN(8809 접두, 교구·세트)이 ISBN으로 섞인 잡음 제거 (978/979 검증)

## 6. 대출건수 필드의 정확한 의미 (오독 방지)

- **다년 누적 스톡**이다. 월 파일의 값 = 데이터 제공 개시(~2014년 추정)부터 그 월까지 합.
  근거: 최고(最古) 파일(2017-07)에 이미 잔액 존재(10.8만 건), 9년 창 대조에서 감소
  0.8%뿐(사실상 단조), 구간 장서 평균 2.8건으로 "도서관 개관 이래 전체"는 아님.
- 따라서 "최근 N년"은 반드시 **두 스냅샷의 차분**으로 만든다. 음수는 0으로 클램프
  (폐기·정정 노이즈 0.8%). 합류 13개월 미만 관은 차분 불가 → 플래그 후 가중 감쇠.
- 관마다 누적 창 길이가 다르므로(60~120개월) **누적 절대값의 관 간 비교는 금지**.

## 7. 외서 처리 (제외 검토 결과)

- **명작은 외서 제외와 무관하다.** 번역서는 한국 ISBN의 한국서다. 실측: 해리포터
  한국어판 311판본·대출 39.9만, 어린왕자 692판본·26.1만, 트와일라잇 8판본 존재.
- 고수요 외서의 실체는 **아동 영어 원서**(Winnie·Froggy·Arthur — 대출 상위 25건 전부)
  = 영어교육 수요라는 독립 용도.
- 결정: **L0 유지, L1 제외 가능** (대출량 4.6% 손실 = 타깃 정렬로 문서화 가능).
  제외 시 카카오 3.3일 절약. 원서 기능 추가 시 데이터는 이미 있다.

> 결론만큼 중요하기 때문이다.

### 결정

**수집 순서**는 그대로다. 정보나루로 먼저 훑는다 — 결측을 메우는 힘이 압도적이다.

**임베딩 입력**은 바뀐다. 정보나루가 채운 책에도 **카카오 소개문을 함께 넣는다.**
"잔여분 전용" 이면 정보나루가 채운 책은 카카오 텍스트를 영영 못 받는데,
두 소스의 내용이 **65.9% 비중복**이라 그만큼을 버리는 셈이었다.

```
임베딩 입력  제목 + 정보나루 소개문 + 키워드 + 카카오 소개문
             (소스별로 따로 임베딩해 평균, 또는 이어붙이되 창 512)
```

### 근거 1 — 품질 (표본 43,290 · 잡음 폭 0.36%p)

주 지표는 **함께대출 일치도**다. 정답을 분류표가 아니라 실제 이용자 행동
(`coLoanBooks` · `maniaRecBooks` · `readerRecBooks`)에서 가져온다.

| 측정 방식 | 정보나루 단독 → 조합 | 차이 |
| --- | --- | ---: |
| 창 128 | 14.38% → 17.44% | +3.06%p |
| 창 512 | 14.41% → 18.04% | **+3.63%p** |
| 소스별 평균 | 14.38% → 17.91% | +3.53%p |

잡음 폭의 **열 배**를 넘는다. 1위는 소스별 따로 임베딩 후 평균
`제목+정보나루 ‖ 카카오 ‖ 키워드` = 적중@10 **20.01%**, 무작위의 554배.

산출물: `database/_pipeline/reports/kakao_combined_experiment.json`

### 근거 2 — 커버리지 재측정 (59,597권, 파일럿의 102배)

582건 파일럿은 층을 **"카카오 약점 순"** 으로 뽑아 모집단 비례가 아니었다.
그래서 절대 수준이 크게 낮게 나왔다.

| | 582건 파일럿 | 59,597권 재측정 |
| --- | ---: | ---: |
| 정보나루 단독 | 70.7% | **92.6%** |
| 카카오 단독 | 50.2% | **78.4%** |
| 합집합 | 73.4% | **94.1%** |
| 정보나루가 더하는 것 | +23.1%p | +15.6%p |
| **카카오가 더하는 것** | **+2.7%p** | **+1.4%p** |

**정책 근거였던 +2.7%p 는 실제로 +1.4%p 였다.** 582건에서 2.7% 는 책 16권이고,
그 값의 표준오차가 0.5%p 다. **16권짜리 근거로 정책을 정한 셈이다.**

즉 **커버리지로는 카카오를 정당화할 수 없고, 내용(임베딩 입력)으로만 정당화된다.**
방향은 같지만 이유가 정반대로 뒤집혔다.

### 곁들여 발견 — 임베딩이 128 토큰에서 잘리고 있었다

`ko-sroberta-multitask` 의 `max_seq_length` 기본값이 **128** 이다.
한국어 실측: 155자→75토큰, 235자→114토큰, **391자→186토큰(잘림)**, 533자→206토큰(잘림).

창을 512 로 늘리면 **잘리던 군만** 오른다 — 짧은 군은 ±0.03%p(잡음 이내),
`정보나루+카카오` +0.60%p, `전부` +1.75%p. 대칭이 완벽해 절단이 원인임이 확실하다.
`T+D+K` 와 `T+D+K+KW` 의 수치가 소수점까지 같았던 것이 증거였다.

**운영 임베딩 파이프라인은 창 512 를 쓰거나 소스별로 나눠 임베딩해야 한다.**

### 국중 회수 텍스트는 보강재가 아니라 대체재다

목차(79,235권·중앙 699자)·소개(74,694권·중앙 974자)를 같은 방법으로 쟀다.
**강한 조합에 섞으면 오히려 나빠진다.**

| | 조합 단독 | 국중 텍스트 추가 |
| --- | ---: | ---: |
| 목차 (n=9,775) | 10.33% | 10.10% (−0.23%p) |
| 국중소개 (n=9,872) | 8.61% | 7.50% (−1.11%p) |

키워드가 이미 더 깔끔하게 주는 주제 정보를 700~1,100자 텍스트가 희석시킨다.
다만 KDC 적중률은 반대로 오른다 — **긴 출판사 홍보문은 분야는 잘 설명하지만
왜 같이 빌리는지는 못 담는다.** 사전 등록 규칙대로 주 지표를 따른다.

따라서 국중 텍스트는 **정보나루·카카오가 모두 없는 책에만** 쓴다.

### 수집 범위

카카오 키 5개(일 15만)로 L1 전량은 약 6.6일이다. 다만 실험 표본이
**1단계 수요 상위 구간**이므로, 꼬리까지 다 채우는 것보다
**1단계 밴드 미수집분을 우선**한다. 큐 순서가 이미 그렇게 잡혀 있다.

### 폐기한 판정 (2026-08-27 ~ 09-02)

> 보강 대상을 정보나루로 먼저 전량 훑고, **카카오는 정보나루가 못 채운 구간에만
> 선별 적용한다.** 근거는 층화 파일럿 582건의 확보율 —
> 정보나루 70.7% / 카카오 50.2% / 합집합 73.4%. 정보나루는 카카오 위에 +23.1%p 를
> 더하는데 카카오는 +2.7%p 뿐이므로, 4.7일을 쓰고 얻는 순증이 2.7%p 라 기각한다.

**무엇이 틀렸나**

1. **표본이 작고 편향됐다.** 582건, 그것도 "카카오 약점 순" 층화.
   재측정하니 절대 수준이 70.7% → 92.6% 로 달랐다.
2. **질문이 섞였다.** "결측을 누가 메우나"(정보나루)와 "임베딩 입력으로 뭐가
   좋나"(둘 다)는 다른 질문인데, 앞의 답으로 뒤의 정책까지 정했다.
3. **하루 뒤 나온 임베딩 증거를 반영하지 않았다.** 이 문서가 08-27,
   임베딩 실험이 08-28 이다.
